# 5. 설계사 앱 기능/UI/UX 명세

## 5-1. 목표
기존 설계사 앱에 최소 수정으로 고객 앱 연결, 청구 요청 관리, 고객용 소식지 발행 기능을 붙인다.

## 5-2. 새 메뉴
### 메뉴명
- `청구 요청`

### 위치
- 기존 고객 관련 메뉴와 자연스럽게 인접한 위치
- 전체 레이아웃 구조를 크게 흔들지 말 것

## 5-3. 고객 상세 화면 추가 기능
고객 상세 화면 또는 고객 카드 영역에 아래 버튼 추가를 권장한다.

- `고객 앱 연결 링크`
- `고객 앱 연결 상태`
- `청구 요청 보기`

### 연결 링크 버튼 동작
- customer_id 기준 링크 생성
- 링크 복사 / 문자 공유 / 카카오 공유(나중) 중 최소 복사 기능 제공
- 이미 생성된 링크가 있으면 재사용 또는 재발급 정책 명확히

### 연결 상태 표시
- 연결 여부
- 마지막 연결 시각
- 디바이스 수
- 필요 시 재연결 링크 재발급

## 5-4. 청구 요청 리스트 UX
### 목록 컬럼 권장
- 접수일시
- 고객명
- 상태
- 첨부 개수
- 제목 또는 한 줄 요약
- 관리

### 필터
- 상태별 필터
- 고객 검색
- 최신순 정렬 기본

### 강조
- `requested` 상태를 가장 눈에 띄게
- 처리중/완료 구분 명확히

## 5-5. 청구 요청 상세 UX
표시 항목:
- 고객명
- 접수일시
- 상태
- 제목
- 메모
- 첨부 파일 리스트
- 상태 변경 이력

버튼:
- 처리중으로 변경
- 완료 처리
- 반려 처리(선택)
- 고객 정보 바로가기

### 첨부 파일 UX
- 이미지 미리보기
- PDF 열기/다운로드
- 파일명/용량 표기

## 5-6. 고객용 소식지 등록 UX
기존 소식지 등록 화면을 재사용 가능하면 재사용한다.  
단, 아래 옵션은 반드시 있어야 한다.

- 고객 앱 노출 여부
- 푸시 발송 여부
- 중요 공지 여부(선택)

### 주의
- 설계사용 내부 게시판 글과 고객용 소식지 글을 혼동하지 않게 해야 한다.
- 고객에게 노출되는 글만 고객 앱 API에서 반환해야 한다.

## 5-7. 설계사 앱 구현 시 유의점
- 기존 고객 관리 UI를 크게 뒤엎지 말 것
- 새 메뉴/버튼은 작고 명확하게 추가할 것
- 연결 링크 생성 로직을 고객별로 정확히 구분할 것
- 고객 링크를 잘못 보내는 실수를 줄이기 위해 고객명 확인 UI를 넣을 것
- 상태 변경 시 즉시 UI 반영 및 서버 이력 저장을 맞출 것

## 5-8. 절대 하지 말 것
- 청구 요청 메뉴에 불필요한 통계/차트부터 넣기
- 설계사가 요청을 직접 삭제하게 만들기
- 고객용 소식지를 설계사 내부 글과 섞어서 노출하기
- 상태값을 프론트 로컬 상태만 바꾸고 서버 이력을 안 남기기
- 기존 고객 상세 플로우를 깨는 구조 변경
