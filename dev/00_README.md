# 고객 청구 요청 앱 개발 패키지

이 폴더는 **설계사 앱 + 고객 앱 + 서버 + DB + 푸시 구조**를 한 번에 개발하기 위한 실행 문서 세트다.  
개발자는 이 문서 순서대로 구현하면 된다.

## 문서 사용 순서
1. `01_PRODUCT_OVERVIEW.md`
2. `02_ARCHITECTURE_AND_RULES.md`
3. `03_DATABASE_SPEC.md`
4. `04_API_SPEC.md`
5. `05_AGENT_APP_SPEC.md`
6. `06_CUSTOMER_APP_SPEC.md`
7. `07_NOTIFICATION_AND_LINKING_SPEC.md`
8. `08_IMPLEMENTATION_STEPS.md`
9. `09_QA_CHECKLIST.md`
10. `10_DONT_DO_THIS.md`

## 핵심 원칙
- 고객 앱은 **청구 요청 보조 앱**이다. 보험사 청구 자동화 앱이 아니다.
- 고객은 **앱 설치 → 링크 연결 → 파일 첨부 → 요청 전송**까지만 한다.
- 설계사는 기존 시스템에서 요청을 확인하고 직접 처리한다.
- 고객 식별은 **설계사(agent_id) + 고객(customer_id) + 디바이스(device_id)** 연결 구조로 고정한다.
- 고객 로그인은 복잡하게 만들지 않는다. 아이디/비밀번호 기반 로그인도 하지 않는다.
- 고객 앱은 하나만 운영한다. 설계사별 앱을 만들지 않는다.

## 최종 산출 목표
- 고객용 모바일 앱(Expo/React Native 기준)
- 기존 설계사용 웹/앱에 “청구 요청” 메뉴 추가
- 링크 연결 구조
- 고객 파일 업로드 및 요청 생성
- 설계사 소식지의 고객 앱 자동 노출
- 푸시 알림
- 운영/보안/검수 기준 포함

## 개발 지시 방식
이 dev 폴더 전체를 프로젝트의 개발 문서 폴더에 넣고 아래처럼 지시한다.

> dev/customer-claim-app-dev-package 폴더의 문서를 1번부터 순서대로 읽고 구현해라.  
> 기존 앱 구조를 최대한 유지하고, 명시된 범위 밖의 UI/로직은 수정하지 마라.  
> 각 단계 완료 시 문서 기준으로 체크리스트를 함께 제출해라.
