# 8. 구현 순서 지시서

## 8-0. 전체 원칙
이 문서는 실제 구현 순서다.  
반드시 아래 순서를 지킨다. UI부터 만들지 말고, 데이터 흐름부터 완성한다.

---

## STEP 1. DB 마이그레이션
### 작업
- 신규 테이블 생성
- 인덱스 생성
- 상태값 규칙 정리
- 기존 소식지 테이블 재사용 여부 확정

### 완료 기준
- 마이그레이션 적용 성공
- 기본 CRUD 테스트 가능
- 기존 데이터와 충돌 없음

### 유의
- 컬럼명 일관성 유지
- created_at / updated_at 기본 제공
- FK는 실제 운영 구조에 맞게 신중히

---

## STEP 2. 링크 생성/연결 API
### 작업
- 설계사 앱용 링크 생성 API
- 고객 앱용 connect API
- audit log 저장
- 고객 앱 토큰 발급

### 완료 기준
- 고객별 링크 생성 가능
- 링크 클릭 후 고객/설계사/디바이스 연결 저장
- 잘못된 링크는 실패 처리됨

### 유의
- 동일 링크 재사용 정책 명확히
- 중복 연결 처리 정책 명확히
- device_id 없을 때 예외 처리

---

## STEP 3. 고객 앱 기본 골격
### 작업
- Expo 프로젝트 또는 기존 앱 구조 생성
- Deep Link / Universal Link 연결
- 연결 성공/실패 화면
- appToken 저장 구조

### 완료 기준
- 링크 클릭 시 앱 열림
- connect API 호출 성공
- 연결 상태가 앱 재실행 후 유지

### 유의
- 로그인 화면 만들지 말 것
- 연결 중 로딩/에러 UX 확실히

---

## STEP 4. 파일 업로드 presign + R2 연결
### 작업
- 고객 앱 파일 선택
- presign 발급
- PUT 업로드
- 업로드 결과 관리

### 완료 기준
- 이미지/PDF 업로드 성공
- storageKey 반환 가능
- 실패 시 재시도 가능

### 유의
- 파일 크기/형식 검증
- 업로드 중 앱 종료/이탈 고려
- orphan 파일 정리 정책 필요

---

## STEP 5. 청구 요청 생성 API + 고객 앱 작성 화면
### 작업
- 요청 생성 API
- 파일 배열 포함 저장
- 고객 앱 작성 화면 구현
- 전송 완료 화면

### 완료 기준
- 고객이 실제 요청 생성 가능
- DB에 요청과 파일이 연결됨
- 설계사 앱에서 조회 가능한 데이터 준비 완료

### 유의
- 연결 안 된 고객은 요청 금지
- 파일 없이 요청 허용 여부 정책 명확히
- 중복 전송 방지

---

## STEP 6. 설계사 앱 “청구 요청” 메뉴
### 작업
- 메뉴 추가
- 리스트 화면
- 상세 화면
- 상태 변경 API 연동

### 완료 기준
- 설계사가 요청 확인 가능
- 첨부 열람 가능
- 상태 변경 가능
- 상태 변경 이력 저장됨

### 유의
- 기존 고객 관리 UI 크게 흔들지 말 것
- 새 요청 강조 표시 필요
- 상태 변경 후 즉시 화면 반영

---

## STEP 7. 고객 요청 내역 화면
### 작업
- 고객 앱 요청 리스트
- 상세 화면
- 상태 표시

### 완료 기준
- 고객이 보낸 요청 목록 확인 가능
- 상태값이 설계사 처리 상태와 맞음

### 유의
- 너무 많은 상세 항목 넣지 말 것
- 고객에게 내부 처리 메모를 노출하지 말 것

---

## STEP 8. 고객용 소식지 API 및 고객 앱 소식지 화면
### 작업
- 기존 소식지 데이터에서 고객 노출 대상만 반환하는 API
- 고객 앱 리스트/상세
- 읽음 처리

### 완료 기준
- 연결된 설계사의 소식지가 고객 앱에 노출됨
- 안 읽은 글 구분 가능

### 유의
- 설계사 내부용 글과 혼선 금지
- 고객 앱은 자동 필터만 사용할 것

---

## STEP 9. 푸시 알림
### 작업
- 푸시 토큰 등록
- 소식지 등록 시 푸시 발송
- 상태 변경 시 푸시 발송

### 완료 기준
- 테스트 기기에서 푸시 수신 성공
- 중복/과도 발송 없음
- 실패 로그 확인 가능

### 유의
- 푸시 먼저 붙이지 말 것
- 발송 대상 필터 정확히
- 실패 시 앱 기능 자체는 막히지 않게

---

## STEP 10. UI/UX 정리
### 작업
- 고객 앱 문구 정리
- 설계사 앱 버튼/레이아웃 미세 조정
- 상태 색상/카드/가독성 정리

### 완료 기준
- 고객이 설명 없이도 요청 보낼 수 있음
- 설계사가 새 메뉴를 헷갈리지 않음

### 유의
- 기능 추가 욕심 금지
- 이번 단계는 polish 단계다

---

## STEP 11. 운영/관리 기능
### 작업
- 연결 상태 보기
- 재연결 링크 발급
- 연결 로그 보기(관리자 또는 내부용)
- orphan 파일 정리 배치 검토

### 완료 기준
- 운영 중 장애 대응 가능
- 연결 문제 추적 가능

---

## STEP 12. 실사용 전 점검
### 작업
- QA 문서 기준 전체 점검
- 테스트 계정/실기기 점검
- 파일 업로드/푸시/상태값 확인

### 완료 기준
- 최소 1명의 설계사 + 1명의 고객 시나리오 완주
- 앱 삭제/재설치/재연결 테스트 완료
