# 6. 고객 앱 기능/UI/UX 명세

## 6-1. 목표
고객이 고민 없이 앱을 열고 요청을 보낼 수 있어야 한다.  
핵심 UX는 **“앱 설치 → 링크 연결 → 파일 올리기 → 전송”** 이다.

## 6-2. 고객 앱 전체 화면 구성
1. 연결 화면
2. 홈 화면
3. 청구 요청 작성 화면
4. 요청 내역 리스트
5. 요청 상세
6. 소식지 리스트
7. 소식지 상세
8. 설정/정보 화면

## 6-3. 연결 화면
### 진입 케이스
- 앱이 링크로 열림
- 앱 설치 후 처음 실행
- 재연결 필요 시

### 표시 요소
- 담당 설계사 연결 안내 문구
- 링크 연결 처리 중 상태
- 연결 성공/실패 결과
- 재시도 버튼

### 성공 시
- 설계사명
- 고객명
- 연결 완료 안내

### 실패 시
- 링크가 유효하지 않음
- 이미 만료됨
- 다시 받아야 함
- 고객센터/설계사 문의 문구

## 6-4. 홈 화면
최대한 단순하게 구성한다.

### 추천 구성
상단:
- 담당 설계사명
- 연결된 고객명

중앙:
- `청구 요청하기` 큰 버튼 1개

하단:
- 최근 소식지 3개
- 최근 요청 상태 요약 1~3개

### 절대 하지 말 것
- 메뉴를 너무 많이 두지 말 것
- 배너/카드/설명을 과하게 넣지 말 것

## 6-5. 청구 요청 작성 화면
### 입력 항목
- 제목(선택 또는 간단 필수)
- 내용/메모(선택 또는 짧게)
- 파일 첨부(필수에 가깝게 UX 설계)
- 전송 버튼

### UX 원칙
- 한 화면에서 끝내는 것을 우선
- 사진 촬영 / 앨범 선택 모두 지원
- 업로드 진행 상태 표시
- 업로드 중 이탈 방지
- 성공 시 “요청이 전송되었습니다” 명확하게 보여주기

### 파일 정책
- 이미지, PDF 우선
- 파일 개수 제한 명시
- 용량 제한 명시

## 6-6. 요청 내역 리스트
표시 항목:
- 요청일
- 제목 또는 요약
- 상태
- 첨부 개수

상태 표시:
- 요청됨
- 처리중
- 완료

## 6-7. 소식지 리스트
### 원칙
- 고객이 따로 고르지 않는다.
- 연결된 설계사의 고객용 소식지만 자동 노출한다.

### 표시 요소
- 제목
- 등록일
- 중요 표시
- 읽음/안읽음

## 6-8. 설정/정보 화면
최소 항목만 둔다.
- 연결된 설계사 정보
- 앱 버전
- 푸시 알림 상태
- 설계사 다시 연결
- 앱 문의 안내

## 6-9. 고객 앱 UX에서 꼭 지켜야 할 것
- 고객이 회원가입한다고 느끼지 않게 만들 것
- 입력을 최소화할 것
- 버튼명을 쉬운 말로 쓸 것
- 복잡한 폼 금지
- 연결/전송 성공 여부를 확실히 보여줄 것
- 첨부가 실제로 올라갔는지 시각적으로 보이게 할 것

## 6-10. 절대 하지 말 것
- 로그인 폼 만들기
- 비밀번호 만들기
- 생년월일 로그인
- 약관/설정/동의 화면을 길게 구성하기
- 고객이 자기 설계사를 수동 검색하게 만들기
- 고객에게 게시판 카테고리 선택을 강요하기
