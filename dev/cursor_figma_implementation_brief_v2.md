# Cursor 작업 지시문 — 보험OA 피그마 2페이지 웹 구현

## 목적
아래 두 개의 Figma 디자인을 현재 프로젝트 코드베이스 안에 실제 웹 페이지로 최대한 동일하게 구현한다.

- Figma 1  
  https://www.figma.com/design/CyvhjYyjTiMrJK8C3RPOZA/%EB%B3%B4%ED%97%98OA%EC%86%8C%EA%B0%9C?node-id=3-314&t=sh5du78xwUvG51Ry-0

- Figma 2  
  https://www.figma.com/design/CyvhjYyjTiMrJK8C3RPOZA/%EB%B3%B4%ED%97%98OA%EC%86%8C%EA%B0%9C?node-id=9-810&t=sh5du78xwUvG51Ry-0

중요:
Cursor도 Figma MCP가 연결되어 있으므로, 반드시 두 노드의 디자인 컨텍스트를 직접 읽고 작업한다.
대충 비슷하게 만드는 것이 아니라 레이아웃, 간격, 카드 구조, 타이포 위계, 색상 분위기, 섹션 흐름을 최대한 동일하게 맞춘다.

---

## 최우선 목표
1. 두 페이지를 현재 프로젝트 안에서 실제 동작하는 웹 페이지로 구현
2. 피그마의 톤앤매너와 시각 구조를 최대한 동일하게 재현
3. 현재 프로젝트의 기술스택/스타일 시스템에 맞게 변환
4. Tailwind를 새로 도입하지 말고, 기존 스타일 방식으로 구현
5. 반응형까지 고려하되, 우선 데스크탑 기준 시안 일치도를 가장 높게 맞춘다
6. 페이지2는 최신 피그마 기준으로 고객앱 다운로드 / 연락처 엑셀 업로드 / GPT 변환 요청 방법 / 하단 요약 CTA까지 포함해 구현한다

## 작업 방식
1. Figma MCP로 각 노드의 구조를 직접 읽는다.
2. 레이아웃, spacing, section height, card size, shadow, radius, typography hierarchy를 확인한다.
3. 현재 프로젝트 코드 스타일에 맞춰 변환 구현한다.
4. 필요한 공통 섹션/카드는 재사용 컴포넌트로 분리하되, 디자인이 틀어지지 않게 한다.
5. 아이콘/이미지는 가능한 한 동일하거나 매우 유사하게 반영한다.
6. 텍스트는 피그마 기준 문구를 우선 반영한다.
7. 구현 후 두 페이지 간 브랜드 일관성이 유지되도록 정리한다.

- 설명:

- 긴 복사 카드 / 코드박스 형태 섹션 구현
- 우측 상단 복사 버튼 UI 반영
- 배경은 진한 네이비 계열 코드박스 느낌 유지
- 긴 텍스트가 들어가도 가독성 있게 padding / line-height / font-size 조정
- 아래 프롬프트를 그대로 반영:

다음 작업을 수행해줘.

[목표]
기존 고객 엑셀 데이터를, 제공한 "샘플 엑셀 양식"과 100% 동일한 구조로 변환하여 작성해줘.
(업로드 시 오류가 발생하지 않도록 데이터 형식까지 정확히 맞출 것)

---

[입력 데이터]

1. 기존 고객 데이터 엑셀 파일
2. 샘플 엑셀 양식 파일

---

[작업 지시]

1. 샘플 엑셀의 컬럼명, 컬럼 순서, 구조를 절대 변경하지 말고 그대로 유지한다.
2. 기존 데이터의 각 항목을 샘플 양식에 맞게 정확하게 매핑한다.
3. 매핑이 애매한 경우, 가장 유사한 항목에 넣고 그 기준을 함께 설명한다.

---

[데이터 형식 규칙 - 매우 중요]

1. 주민번호, 휴대폰번호, 차량번호, 계좌번호 등은 반드시 "텍스트 형식"으로 처리한다.
   (숫자 변환 금지, 앞자리 0 절대 유지)

2. 주민번호와 휴대폰번호는 "샘플 양식 기준"을 따른다.

   * 샘플에 하이픈이 없으면 → 숫자만 입력
   * 샘플에 하이픈이 있으면 → 동일하게 입력

3. 날짜는 반드시 아래 형식으로 통일한다
   → yyyy-mm-dd

4. 빈 값은 다음과 같이 처리한다

   * 데이터 없으면 → 빈칸 유지
   * "없음", "null", "-" 등 입력 금지

5. 모든 셀은 줄바꿈 없이 한 줄로 작성한다 (Enter 금지)

6. 텍스트 앞뒤 공백 제거 (trim 처리)

7. 특수문자 및 불필요한 기호 제거

---

[데이터 정리 규칙]

1. 동일 고객이 중복될 경우 하나로 정리한다
   (주민번호 기준으로 판단)

2. 주소는 하나의 필드로 합쳐서 작성한다 (줄바꿈 금지)

3. 긴 텍스트는 줄바꿈 없이 한 줄로 정리

4. 숫자 데이터는 자동 변환되지 않도록 반드시 텍스트 처리

5. 성별은 주민번호 기준으로 자동 판단하여 입력한다

   * 주민번호 뒷자리 첫 숫자 기준
   * 1, 3 → 남성
   * 2, 4 → 여성
   * 기타 값은 빈칸 처리

---

[출력 형식]

1. 결과는 "샘플 엑셀 구조 그대로" 유지하여 출력한다
2. 먼저 표 형태로 보여주고, 이후 엑셀 파일로 다운로드 가능하게 제공한다

---

[중요]

* 샘플 엑셀 구조 절대 변경 금지
* 데이터 형식 오류 없이 업로드 가능해야 함
* 데이터 정확성이 가장 중요

---

[추가 요청]

변환 결과에서 다음 항목을 함께 검증해줘:

* 주민번호 길이 이상 여부 (13자리)
* 전화번호 형식 오류 여부 (11자리)
* 필수값 누락 여부
* 성별 자동 판별 불가 데이터

문제가 있는 데이터는 따로 표시해줘.
문의가 필요한 경우 관리자에게 요청해 주세요.

## 스타일/디자인 토큰 가이드
반드시 피그마 기준으로 최대한 맞춘다.

색감 기준:
- 메인 블루: #2563EB 계열
- 배경: #F8FAFC / #FFFFFF 계열
- 본문 다크: #111827 계열
- 서브 텍스트: #6B7280 계열
- 보더: #E5E7EB 계열

느낌:
- radius 큼 (14px~16px 이상 느낌)
- shadow 부드럽고 넓게
- 버튼은 둥글고 명확한 중심 정렬
- 카드 안 텍스트 간격 여유 있게
- 섹션 패딩 충분히 크게

타이포 방향:
- Hero 제목은 매우 크고 두껍게
- 섹션 제목은 굵고 중앙 정렬
- 본문은 16~20px 전후의 정돈된 가독성
- 설명 텍스트는 너무 작게 만들지 말 것

## 기술 구현 요구
1. 현재 프로젝트 라우터 구조 확인 후
   - 소개 메인 페이지 라우트 추가
   - 설치 안내 페이지 라우트 추가

2. 페이지 파일은 분리
- 예: IntroductionPage
- 예: IntroductionInstallPage
실제 프로젝트 네이밍 규칙에 맞게 작성

3. 공통 컴포넌트 분리 가능
- SectionTitle
- FeatureCard
- DownloadCard
- StepCard
- PromptCodeBlock
등
단, 재사용보다 시안 일치도가 우선

4. CSS는 현재 프로젝트 방식에 맞춰 작성
- CSS module / scoped style / 기존 index.css 패턴 등 현재 저장소 규칙 따를 것

5. 반응형
- 데스크탑 우선 정밀 구현
- 태블릿/모바일에서는 세로로 자연스럽게 쌓이도록 처리
- 하지만 데스크탑 시안이 우선이다

## 텍스트 반영 원칙
텍스트는 피그마에 보이는 문구를 우선 반영한다.
임의 요약 금지.
특히 설치 안내 단계 문구, 업로드 안내 문구, GPT 프롬프트는 최대한 그대로 반영한다.

## 작업 완료 후 꼭 할 일
1. 어떤 파일을 생성/수정했는지 정리
2. 라우트 경로 정리
3. 피그마 대비 어떤 부분을 동일하게 맞췄는지 설명
4. 아직 링크가 없는 항목이나 placeholder 처리한 항목이 있으면 명확히 설명
5. 로컬 빌드 또는 타입체크까지 확인
6. 다운로드 버튼 3종이 실제 링크로 정확히 연결되었는지 확인

## 최종 요청
핵심은 보험OA 소개 피그마 두 페이지를 현재 프로젝트 안에 거의 동일하게 재현하는 것이다.
단순한 참고 구현이 아니라 실제 운영 페이지로 바로 연결 가능한 수준으로 만든다.
특히 페이지2는 반드시 최신 피그마 node 9:810 기준으로 구현하고,
PC 다운로드 / FC 모바일 / 고객앱 다운로드 링크를 실제 파일 링크로 연결한다.
