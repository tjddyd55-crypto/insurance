# 🔴 고객관리 리팩토링 - 초정밀 통제형 지시문 (Cursor 전용)

## 🎯 목적
이 작업은 기능 추가가 아니라 **기존 코드 기반 안정화 리팩토링**이다.
절대 새로 만들지 말고, 반드시 **현재 코드 → 분석 → 최소 수정**으로 진행한다.

---

# 🚨 절대 규칙 (위반 금지)

1. 기존 코드 먼저 찾고 읽은 후 수정한다.
2. 한 번에 많은 파일 수정 금지
3. 새 구조/새 패턴 도입 금지
4. window.confirm 사용 금지
5. 전체 refetch / reload 금지
6. 기존 공통 컴포넌트 삭제 금지
7. virtualization 무리하게 적용 금지

---

# 🧠 STEP 0 — 반드시 먼저 수행

아래 항목을 **코드에서 실제 위치를 찾아라**

- 고객등록 페이지 컴포넌트
- 뒤로가기 처리 코드 (BackHandler / router)
- ExitConfirmDialog
- AppExitConfirm
- 즐겨찾기 토글 함수
- 메모 저장 함수
- 고객 리스트 렌더링 컴포넌트

👉 찾은 후 각각 파일 경로 기록

---

# 🧠 STEP 1 — 뒤로가기 충돌 해결

## 조건 확인

IF:
- 고객등록 페이지에서
- ExitConfirmDialog 존재
- AppExitConfirm도 존재

THEN:
👉 충돌 발생 상태

---

## 수정

1. 고객등록 페이지 진입 시:
   - BackHandler에서 return true 처리

2. ExitConfirmDialog 열려있을 때:
   - 추가 뒤로가기 이벤트 차단

3. AppExitConfirm:
   - 고객등록에서는 실행 금지 조건 추가

---

## 결과

- 뒤로가기 → 모달 1개만 표시
- 앱 종료 중복 제거

---

# 🧠 STEP 2 — 즐겨찾기 수정

## 현재 구조 찾기

IF:
- toggle 후 API 호출 후
- 전체 리스트 fetch

👉 이 코드 제거

---

## 수정

1. setState로 먼저 UI 변경
2. API 호출
3. 실패 시 rollback

---

## 결과

- 별표 즉시 반응
- 전체 깜빡임 없음

---

# 🧠 STEP 3 — 메모 저장 수정

## 현재 구조 찾기

IF:
- 저장 후 전체 리스트 fetch

👉 제거

---

## 수정

- 해당 고객만 업데이트

---

# 🧠 STEP 4 — 리스트 성능

## 1단계 (필수)

- CustomerCard → React.memo 적용
- key → id 기반인지 확인
- inline 객체 제거

---

## 2단계 (조건부)

- 검색 입력 시 즉시 렌더링 과다

## 3단계 (금지 조건 포함)

THEN:
